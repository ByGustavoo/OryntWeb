# Desenvolvimento: simulador, Vite e verificação no Chrome

* Without a `.env`, the app runs on simulated data (`VITE_FONTE_DADOS=simulada`). With `VITE_FONTE_DADOS=api`, the simulator is not bundled (checked by building both ways).
* Checking the query list through the Chrome extension: while the Chrome window was covered by another one, the first click after a navigation was not delivered to the page (no event reached `document`) and smooth scrolling did not run, so drive it with `element.click()` from the page when that happens. Replace `HTMLAnchorElement.prototype.click`, `URL.createObjectURL` and `navigator.clipboard.writeText` before touching "Exportar CSV" or "Copiar".
* The connection scenario panel (`PainelSimulacao`, inside the modal) and `window.oryntSimulacao` exist only in development. Console controls: `cenario('SENHA_INCORRETA' | 'SERVIDOR_INACESSIVEL' | 'BANCO_INEXISTENTE' | 'TEMPO_ESGOTADO' | 'SUCESSO')` (also applies to activating a saved connection), `falhar('/dashboard')` (`false` turns it off; `falhar('/conexoes')` shows the failed-check state, `falhar('/relatorios')` the error state of the three report screens, `falhar('/consultas')` the error state of Consultas SQL › Todas, Histórico and Planos de execução, `falhar('/objetos')` the error state of Views, Índices, Tabelas and Funções, `falhar('/usuarios')` the error state of Papéis, Sessões and Permissões, `falhar('/administracao')` and `falhar('/auditoria')` the error states of Administração › Usuários and Auditoria), `latencia(8000)`, `esvaziar()` (empty states of the dashboard, of the report screens, of the query list, of Histórico, of Planos de execução, of Views, of Índices, of Tabelas, of Funções, of Papéis, of Sessões and of Permissões; `esvaziar(false)` restores), `restaurarAdministracao()` (back to the demo account only, empty audit, signed out, then reloads), `restaurarPapeis()` (drops every change made through the Orynt in the simulator), `recusarAlteracoes()` (refuses every change with a permission error; `recusarAlteracoes(false)` turns it off; stored), `rastrearFuncoes('none' | 'pl' | 'all')` (the simulated `track_functions` of the server, `pl` by default and stored), `encerrarSessao()` (drops the active connection), `expirarCodigo()` and `expirarRedefinicao()` (end the validity of the recovery code and of the reset token right away; `falhar('/autenticacao/recuperacao')` shows the server error of the three recovery steps), `sair()` (drops login and connection, then reloads on `/login`; the account menu in the header also has a "Sair" button).
* Editing a provider file that also exports its hook makes Vite recreate the context on hot reload, and a lazily loaded page then fails with "precisa estar dentro de"; reload the page before reading that as a bug.
* Vite keeps serving a module under the `?t=` timestamp of its last hot update, and Chrome caches that URL. A file saved twice in a row can leave the browser with the middle version (a `ReferenceError` for something that exists on disk, while `tsc` passes). Restart `npm run dev` before reading that as a bug; saving the file once more (`touch`) and reloading the page was enough on 12 October 2026, when the server could not be restarted.
* Chrome cannot be resized below about 500px, and not at all when maximized; check 320, 390 and 834 widths by loading the app in iframes.
